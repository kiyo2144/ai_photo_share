# コーディング規則

## 1. 基本方針

- Python 3.13、Flask、Peeweeを使用する。
- 初版は単一の`app.py`で構成する。
- 初学者が読める明示的な処理を優先し、不要な抽象化を行わない。
- ルート処理が長くなる場合は、検証、画像保存、権限確認などを短い補助関数へ分ける。
- 新しい依存パッケージや対象外機能を、承認なしに追加しない。
- 名前は役割が分かる英語とし、同じ概念には同じ名前を使う。

## 2. 設計への準拠

- URL、HTTPメソッド、エンドポイント名、テンプレート名は`routes.md`に一致させる。
- 画面項目と遷移は`screens.md`に一致させる。
- モデル、型、キー、制約は`database.md`に一致させる。
- 必須機能と対象外機能は`requirements.md`に従う。
- 仕様が競合して判断できない場合は、推測で実装せず確認する。

## 3. Flaskと設定

- 設定値は`app.config`へ集約する。
- `SECRET_KEY`などの秘密情報をコードへ直書きしない。
- 開発用の`.env`はGitへ登録しない。
- 本番環境でデバッグモードを有効にしない。
- POST成功後はリダイレクトし、再読み込みによる二重送信を防ぐ。
- 利用者向けメッセージは日本語で表示する。

## 4. PeeweeとSQLite

- SQLiteの外部キー制約を接続時に有効化する。
- DB接続はリクエスト前に開き、リクエスト後に閉じる。
- 起動時は不足テーブルだけを作成し、既存テーブルの変更処理として扱わない。
- 複数のDB更新は、必要に応じてトランザクションでまとめる。
- ユニーク制約エラーなど、事前確認だけでは防げないDB例外も処理する。
- 日時は共通関数で日本時間を生成する。
- 投稿作成時は`created_at`と`updated_at`を設定し、編集時は`updated_at`を更新する。

## 5. 認証と権限

- Flask-Loginはユーザーのログイン・ログアウトと保護ルートに使用する。
- Flask-Sessionはログインセッションをサーバー側へ保存するために使用する。
- セッションへパスワードや不要な個人情報を保存しない。
- 投稿、編集、削除、ログアウトではサーバー側でログインを確認する。
- 編集と削除では、対象投稿の`user_id`とログインユーザーのIDを照合する。
- 他人の投稿への操作は403、存在しない投稿は404とする。
- `next`はスキームやホストを含まない、アプリ内の相対パスだけを許可する。

## 6. フォームと入力検証

- すべてのPOSTにFlask-WTFのCSRF対策を適用する。
- ブラウザ側の検証だけに頼らず、サーバー側で再検証する。
- 表示名は前後の空白を除き、必須かつ50文字以内とする。
- メールアドレスは形式を検証し、前後の空白を除いて小文字で保存する。
- キャプションは前後の空白を除き、1〜200文字とする。
- パスワードと画像ファイルの入力値は、エラー後の画面に保持しない。

## 7. パスワードと秘密情報

- Werkzeugのパスワード用関数でハッシュ化と照合を行う。
- パスワードの平文をDB、セッション、ログへ保存しない。
- パスワードの誤りでは、メールアドレスの登録有無を推測できない共通メッセージを使う。
- 秘密鍵や環境変数の値を画面やログへ出さない。

## 8. 画像ファイル

- ユーザー投稿画像の保存先は、プロジェクト直下の`uploads/`とする。
- `static/`はCSSとJavaScript用とし、投稿画像を保存しない。
- 元ファイル名を保存名として使わず、UUIDなどで名前を生成する。
- 保存先を解決し、`uploads/`の外へ出ないことを確認する。
- 拡張子や申告されたMIMEタイプを信用せず、Pillowで実際の画像を検証する。
- JPEG、PNG、WebPだけを許可し、最大容量は10MBとする。
- 検証済みのMIMEタイプ、容量、幅、高さをDBへ保存する。
- 画像を返すルートは、安全なファイル送信機能を使用する。
- DB登録とファイル保存の片方が失敗した場合は、成功した側を取り消す。
- 削除処理の一部が失敗した場合はログへ記録し、不整合を隠さない。

## 9. エラーとログ

- 予想できる入力エラーはフォームへ表示し、内部例外として扱わない。
- 予期しない例外はログへ記録し、利用者には一般的なメッセージだけを表示する。
- ログへパスワード、セッショントークン、CSRFトークン、秘密鍵を記録しない。
- 例外を無条件に握りつぶさない。

## 10. テスト

- pytestは必須機能の完成後に追加する。
- テストでは一時SQLite DB、一時アップロード先、テスト用セッション保存先を使う。
- テストから開発・本番のDBやプロジェクト直下の実データへ触れない。
- 正常系だけでなく、未ログイン、権限不足、不正入力、重複、不正画像も確認する。
- テスト終了後は作成したファイルとDBを確実に片付ける。
