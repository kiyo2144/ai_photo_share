# 写真共有アプリ 要件定義書

## 1. アプリの概要

友人同士で、旅行や日常の写真を気軽に見せ合うための、Instagram風の小規模な写真共有Webアプリを作成する。

- 投稿できる内容は、1件につき写真1枚と短いキャプションとする。
- 投稿一覧はログインしていない人も閲覧できる。
- 写真の投稿、投稿の管理、いいね（余裕があれば追加）にはユーザー登録とログインが必要となる。
- 初版では少人数での利用を想定し、分かりやすさと実装のしやすさを優先する。

## 2. 想定ユーザー

- 旅行や日常の写真を友人に見せたい人
- 友人が投稿した写真を一覧で見たい人
- アカウントを作らず、投稿された写真だけを見たい人

## 3. 必須機能

必須機能は、以下の順番を目安に小さく分けて実装する。

### 3.1 ユーザー登録

- **目的**: 写真を投稿する利用者のアカウントを作成する。
- **利用条件**: ログインしていないこと。
- **正常時の動作**:
  - 公開用の表示名、メールアドレス、パスワードを入力して登録できる。
  - 登録後はログイン画面へ移動する。
- **主なエラー**:
  - 必須項目が入力されていない。
  - 表示名が50文字を超えている。
  - すでに登録されているメールアドレスである。
  - パスワードがアプリで定めた条件を満たしていない。

### 3.2 ログイン・ログアウト

- **目的**: 登録済みユーザーを識別し、投稿などの機能を安全に利用できるようにする。
- **利用条件**:
  - ログインには登録済みのメールアドレスとパスワードが必要となる。
  - ログアウトはログイン中のユーザーだけが利用できる。
- **正常時の動作**:
  - 正しい情報でログインすると、投稿などの会員向け機能を利用できる。
  - ログアウトするとログイン状態が解除される。
- **主なエラー**:
  - メールアドレスまたはパスワードが正しくない。
  - 必須項目が入力されていない。

### 3.3 投稿作成

- **目的**: ユーザーが写真と短い説明を共有できるようにする。
- **利用条件**: ログインしていること。
- **正常時の動作**:
  - 写真を1枚選択して投稿できる。
  - 1文字以上200文字以内のキャプションを付ける。
  - 投稿には投稿者と投稿日時が記録される。
  - 投稿後は投稿一覧で内容を確認できる。
- **主なエラー**:
  - 写真が選択されていない。
  - 対応していない画像形式である。
  - ファイルサイズが上限を超えている。
  - キャプションが未入力または空白だけである。
  - キャプションが200文字を超えている。

### 3.4 投稿一覧

- **目的**: 投稿された写真をまとめて閲覧できるようにする。
- **利用条件**: なし。ログインしていない人も閲覧できる。
- **正常時の動作**:
  - 投稿を新しい順に表示する。
  - 写真、キャプション、投稿者の表示名、投稿日時を表示する。
- **主なエラー**:
  - 投稿がない場合は、その旨を示すメッセージを表示する。
  - 画像を読み込めない場合でも、ページ全体が利用不能にならないようにする。

### 3.5 キャプション編集

- **目的**: 投稿後にキャプションを修正できるようにする。
- **利用条件**: ログイン中で、対象の投稿を作成した本人であること。
- **正常時の動作**:
  - キャプションを200文字以内で変更できる。
  - 保存後、変更した内容が投稿一覧に反映される。
- **主なエラー**:
  - キャプションが200文字を超えている。
  - 対象の投稿が存在しない。
  - 他のユーザーの投稿を編集しようとしている。

### 3.6 投稿削除

- **目的**: 投稿者が不要になった自分の投稿を削除できるようにする。
- **利用条件**: ログイン中で、対象の投稿を作成した本人であること。
- **正常時の動作**:
  - 誤操作を防ぐため、確認してから投稿を削除する。
  - 投稿に関連する画像ファイルも削除する（いいねを追加した後は、関連するいいねも削除する）。
- **主なエラー**:
  - 対象の投稿が存在しない。
  - 他のユーザーの投稿を削除しようとしている。
  - 画像ファイルの削除に失敗した場合は、記録を残して原因を確認できるようにする。

### 3.7 エラー表示

- **目的**: 操作に失敗した理由と、利用者が次に行うことを分かりやすく伝える。
- **利用条件**: 入力の誤り、未ログイン、権限不足などが発生した場合。
- **正常時の動作**:
  - 入力項目の近く、または画面上部に日本語のエラーメッセージを表示する。
  - 入力し直せるエラーでは、可能な範囲で入力内容を保持する。ただし、パスワードは保持しない。
- **主なエラー**:
  - 未ログインで会員向け機能を利用しようとした場合は、ログインが必要なことを示す。
  - 権限のない編集や削除は拒否する。
  - 存在しない投稿を指定した場合は、投稿が見つからないことを示す。
  - 予期しないエラーでは、内部情報を画面に表示しない。

## 4. 余裕があれば追加する機能

以下は、すべての必須機能が完成し、動作確認できた後に追加する。

### 4.1 いいね・いいね解除

- **目的**: 気に入った投稿へ簡単に反応できるようにする。
- **利用条件**: ログインしていること。
- **正常時の動作**:
  - 1つの投稿に1回だけいいねできる。
  - いいね済みの投稿では、いいねを解除できる。
  - 投稿一覧に各投稿のいいね数を表示し、操作結果が反映される。
- **主なエラー**:
  - 同じユーザーによる重複したいいねを登録しようとしている。
  - 対象の投稿が存在しない。

コメント、検索、ユーザーのフォロー、ダイレクトメッセージ、通知、画像加工は今回の対象外とする。

## 5. 非機能要件

### 5.1 使用技術

- WebフレームワークにはFlaskを使用する。
- ORMにはPeeweeを使用する。
- データベースにはSQLiteを使用する。
- HTMLの生成にはFlaskのテンプレート機能を使用する。

### 5.2 画像

- 初版では、画像をアプリが管理するローカルフォルダに保存する。
- 対応形式はJPEG、PNG、WebPとする。
- 1ファイルの最大サイズは10MBとする。
- 将来クラウドストレージへ移行できるよう、データベースには画像本体ではなく保存先を記録する。
- データベースには検証済みの画像形式、ファイル容量、幅、高さも記録する。

### 5.3 セキュリティとプライバシー

- パスワードは平文で保存せず、安全な方式でハッシュ化する。
- メールアドレスはログイン用の情報として扱い、投稿一覧などの公開画面には表示しない。
- 投稿、編集、削除、いいねでは、サーバー側でもログイン状態と操作権限を確認する。
- データを変更するフォームにはCSRF対策を行う。
- アプリの秘密鍵はソースコードへ直接記載せず、環境変数などで管理する。
- 本番環境ではデバッグ機能を無効にする。

### 5.4 保守性

- 初学者が処理の流れを追えるよう、登録、認証、投稿、いいねなどの役割ごとに処理を分ける。
- 1つの処理に多くの役割を持たせず、小さな単位で実装して確認する。
- エラーの原因を調べられるよう、予期しないエラーやファイル操作の失敗をログへ記録する。

## 6. 実装時に注意すべきこと

### 6.1 データ設計

- ユーザーには、公開用の表示名、重複しないメールアドレス、パスワードのハッシュ、登録日時を持たせる。表示名は重複してもよい。
- 投稿には、投稿者、画像の保存先、検証済みの画像形式・容量・幅・高さ、必須のキャプション、投稿日時、更新日時を持たせる。
- いいね（余裕があれば追加）には、ユーザーと投稿の組み合わせを持たせ、その組み合わせが重複しない制約を設定する。投稿を削除するときは、関連するいいねも残らないようにする。

### 6.2 認証と権限

- 画面上でボタンを隠すだけでなく、サーバー側で必ず権限を検証する。
- ログインしていない利用者による投稿、編集、削除、いいねを拒否する。
- 編集と削除では、ログインユーザーが投稿者本人か確認する。
- ログイン後の移動先を受け取る場合は、外部の危険なURLへ転送されないよう検証する。

### 6.3 画像アップロード

- 元のファイル名を保存名としてそのまま使用しない。
- 保存名はUUIDなどを使ってランダムに生成し、ファイル名の衝突や危険なパスを防ぐ。
- 拡張子だけで判断せず、ファイルの内容が実際に対応画像形式であることを確認する。
- 容量超過や不正な画像は、保存する前に拒否する。
- データベースへの登録と画像保存の一方だけが成功した場合に、不整合が残らないよう処理する。

### 6.4 投稿削除

- 投稿のデータ、関連するいいね、画像ファイルを一連の削除対象として扱う。
- データベースの削除とファイル削除の失敗を考慮し、不整合を把握できるようログを残す。
- 削除操作はGETリクエストでは行わず、CSRF対策を適用したフォームから実行する。

### 6.5 実装の進め方

1. Flaskで最小の画面を表示する。
2. PeeweeとSQLiteを接続し、ユーザーを登録できるようにする。
3. ログインとログアウトを追加する。
4. 投稿作成を追加する。
5. 公開の投稿一覧を追加する。
6. 投稿者本人による編集と削除を追加する。
7. 各機能の入力チェック、権限チェック、エラー表示を確認する。
8. （余裕があれば）いいねといいね解除を追加する。

各段階で正常な操作だけでなく、未入力、不正なファイル、未ログイン、他人の投稿への操作も確認してから次へ進む。
