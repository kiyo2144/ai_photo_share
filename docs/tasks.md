# 実装タスク

上から順に実装する。各項目の完了条件を満たしてから次へ進む。初版では単一の`app.py`を使用する。

## 1. プロジェクト設定

- [ ] `.env`から`SECRET_KEY`などを読み込む
- [ ] `instance/`、`uploads/`、`static/`、`templates/`のパスを設定する
- [ ] アップロード上限を10MBに設定する
- [ ] 開発環境以外でデバッグを有効にしない

完了条件: 秘密情報をコードに書かず、Flaskアプリを起動できる。

## 2. DBとモデル

- [ ] SQLiteへ接続し、外部キー制約を有効にする
- [ ] 基底モデル、`User`、`Post`を`database.md`どおりに定義する
- [ ] 起動時に不足しているテーブルだけを安全に作成する
- [ ] リクエスト前後でDB接続を開閉する

完了条件: 起動時に`users`と`posts`が作られ、再起動しても既存データが消えない。

注意: テーブル自動作成は既存カラムを変更しない。モデル構造を変えた開発段階では、必要に応じてローカルDBを作り直す。

## 3. 共通画面

- [ ] `base.html`へヘッダー、ナビゲーション、フラッシュメッセージを作る
- [ ] `static/`へ共通CSSと削除確認用JavaScriptを置く
- [ ] ログイン状態に応じてナビゲーションを切り替える

完了条件: 未ログイン時とログイン時で正しいリンク・ボタンが表示される。

## 4. ユーザー登録

- [ ] 表示名、メールアドレス、パスワード、確認用パスワードのフォームを作る
- [ ] 必須、文字数、メール形式、パスワード一致を検証する
- [ ] メールアドレスを正規化し、重複を拒否する
- [ ] パスワードをハッシュ化して保存する

完了条件: 正常に登録でき、不正入力と重複メールには日本語エラーが表示される。

## 5. ログインとログアウト

- [ ] Flask-Loginのユーザーローダーを設定する
- [ ] Flask-SessionをCacheLibのローカル保存先で設定する
- [ ] ログインフォーム、認証、ログアウトを実装する
- [ ] 安全な`next`だけをログイン後の遷移先として許可する

完了条件: ログイン状態がリクエスト間で維持され、ログアウト後は保護機能を使えない。

## 6. 投稿作成と画像保存

- [ ] 投稿作成フォームを作る
- [ ] 画像形式、容量、幅、高さ、破損の有無をPillowで検証する
- [ ] キャプションが1〜200文字で空白だけでないことを検証する
- [ ] UUIDなどで保存名を生成し、プロジェクト直下の`uploads/`へ保存する
- [ ] 相対保存先と画像メタデータをDBへ保存する
- [ ] 途中で失敗した場合に画像やDBレコードを残さない

完了条件: 正常な画像だけを投稿でき、不正な画像やキャプションは保存されない。

## 7. 投稿一覧と画像表示

- [ ] 投稿を新しい順に投稿者とともに取得する
- [ ] 写真、キャプション、表示名、投稿日時を表示する
- [ ] `uploads/`内の画像だけを返す安全な表示ルートを用意する
- [ ] 投稿がない場合と画像を表示できない場合を扱う

完了条件: 未ログインでも一覧と画像を閲覧でき、メールアドレスは表示されない。

## 8. キャプション編集

- [ ] 一覧内に本人用の編集フォームを表示する
- [ ] ログインと投稿者本人であることをサーバー側で確認する
- [ ] キャプションを再検証し、`updated_at`も更新する

完了条件: 本人だけが有効なキャプションへ更新でき、他人の操作は403になる。

## 9. 投稿削除

- [ ] 本人用の削除フォームと確認ダイアログを作る
- [ ] ログイン、本人、CSRFを検証する
- [ ] 投稿レコードと画像ファイルを削除する
- [ ] 片方の削除に失敗した場合をログへ記録する

完了条件: 本人だけが削除でき、キャンセル時は何も変更されない。

## 10. エラーとセキュリティ

- [ ] 400、403、404、413、500の利用者向け表示を確認する
- [ ] GETで編集、削除、ログアウトできないことを確認する
- [ ] CSRFなしのPOSTが拒否されることを確認する
- [ ] パストラバーサル、不正な`next`、偽装画像を拒否する
- [ ] 秘密情報や内部例外を画面へ表示しない

完了条件: `requirements.md`と`routes.md`の主要エラー条件を手動確認できる。

## 11. 自動テスト

必須機能の完成後にpytestを追加する。

- [ ] 一時SQLite DBと一時アップロード先を使うfixtureを作る
- [ ] 登録、ログイン、ログアウトをテストする
- [ ] 投稿作成、一覧、画像表示をテストする
- [ ] 編集・削除の本人確認をテストする
- [ ] CSRF、入力不正、404、403、413をテストする
- [ ] テスト後に一時ファイルを削除する

完了条件: テストがローカルDBや実際の`uploads/`を変更せず、全件成功する。

## 12. 初版後の任意機能

- [ ] いいね機能を実装するか改めて判断する

投稿詳細、コメント、検索、フォロー、通知、画像加工は、別途要件が追加されるまで実装しない。
